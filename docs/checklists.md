## 1. [待确认] 清单

| # | 事项 | 影响面 | 建议动作 |
|---|---|---|---|
| 1 | Windows 下父目录 fsync（目录句柄 `FlushFileBuffers`）的实际行为与性能未实测；掉电安全为可选启用项（ADR-2/设计 §5.1） | `internal/atomicfile` 可选路径 | 在 Windows 与 POSIX 各做一次掉电模拟验证后再决定是否在文档中给出启用建议 |
| 2 | `ChunkedSink` 块滚动策略当前按「批数」（默认 10）配置；按「字节阈值」滚动是否更普适（适配超大批次场景） | `stream.ChunkedSink` 选项 | 首版只做批数；出现字节敏感场景再加 `WithChunkBytes`（选项向后兼容） |
| 3 | Saga `ActionCtx` 值限定为 JSON 可序列化类型由业务保证；是否在 Save 前主动探测并给出可定位错误 | `saga` Save 路径 | 首版维持契约声明；若测试中出现难定位失败，再加 marshaling 预检 |
| 4 | `Dispatcher.Start` 后台轮询与 ctx 取消的组合需并发测试（轮询中取消、取消后无泄漏）；该模式是否保留在首版 API 面 | `outbox.Dispatcher` | 保留但标注「便利模式」；测试矩阵必须含 Start 的取消路径 |

## 2. 疑点清单（设计内已收敛，留档备查）

| # | 疑点 | 收敛方式 |
|---|---|---|
| 1 | 导出过程 LSN 语义是否随阶段切换（提取期按块/项计，合并期按最终文件字节计） | 由补偿侧配对规则统一：分块管道全程用「累计项数 + Stater 块进度」，最终文件尺寸只在 completed 后有意义；不随阶段切换单位（设计 §5.3/§5.4） |
| 2 | 引擎层除持久化哨兵外是否需要更多类别哨兵（如对齐失败专类） | 不预设；哨兵必须有消费方才引入（设计 §8 约束 2），出现真实 `errors.Is` 调用方再加 |
| 3 | 分页源的页游标与块进度是否可能错位（页不可重放场景） | 页游标经 Stater 与块进度同 checkpoint 原子保存；页不可幂等重放的数据源须自行声明该限制并在适配层转为可重放游标（设计 §5.5 失败模式） |
| 4 | 多实例/多进程写同一状态目录的互斥 | 显式非目标（设计 §9.3）；需求出现时在文件锁/租约/外部协调间重新决策，属破坏性扩展 |
| 5 | 并发多 Dispatcher 重复取走 processing 消息 | 显式单分发器前提（ADR-6）；多分发器需 `ProcessingSince` + 租约超时，属契约扩展 |

## 3. 验收清单（发布前逐项核对）
