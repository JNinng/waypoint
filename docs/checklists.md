## 1. [待确认] 清单

| # | 事项 | 影响面 | 建议动作 |
|---|---|---|---|
| 1 | Windows 下父目录 fsync（目录句柄 `FlushFileBuffers`）的实际行为与性能未实测；掉电安全为可选启用项（ADR-2/设计 §5.1） | `internal/atomicfile` 可选路径 | 在 Windows 与 POSIX 各做一次掉电模拟验证后再决定是否在文档中给出启用建议 |
| 2 | `ChunkedSink` 块滚动策略当前按「批数」（默认 10）配置；按「字节阈值」滚动是否更普适（适配超大批次场景） | `stream.ChunkedSink` 选项 | 首版只做批数；出现字节敏感场景再加 `WithChunkBytes`（选项向后兼容） |
| 3 | Saga `ActionCtx` 值限定为 JSON 可序列化类型由业务保证；是否在 Save 前主动探测并给出可定位错误 | `saga` Save 路径 | 首版维持契约声明；若测试中出现难定位失败，再加 marshaling 预检 |
| 4 | `Dispatcher.Start` 后台轮询与 ctx 取消的组合需并发测试（轮询中取消、取消后无泄漏）；该模式是否保留在首版 API 面 | `outbox.Dispatcher` | 保留但标注「便利模式」；测试矩阵必须含 Start 的取消路径 |
| 5 | `outbox/producer` 的记录源首版只支持「记录数切片」定位；不可由记录数定位的游标型源（文件字节偏移等）暂不支持 | `outbox/producer` | 出现真实游标源场景再加可选 `stream.Stater`（由组件持久化游标，接口向后兼容） |

## 2. 疑点清单（设计内已收敛，留档备查）

| # | 疑点 | 收敛方式 |
|---|---|---|
| 1 | 导出过程 LSN 语义是否随阶段切换（提取期按块/项计，合并期按最终文件字节计） | 由补偿侧配对规则统一：分块管道全程用「累计项数 + Stater 块进度」，最终文件尺寸只在 completed 后有意义；不随阶段切换单位（设计 §5.3/§5.4） |
| 2 | 引擎层除持久化哨兵外是否需要更多类别哨兵（如对齐失败专类） | 不预设；哨兵必须有消费方才引入（设计 §8 约束 2），出现真实 `errors.Is` 调用方再加 |
| 3 | 分页源的页游标与块进度是否可能错位（页不可重放场景） | 页游标经 Stater 与块进度同 checkpoint 原子保存；页不可幂等重放的数据源须自行声明该限制并在适配层转为可重放游标（设计 §5.5 失败模式） |
| 4 | 多实例/多进程写同一状态目录的互斥 | 显式非目标（设计 §9.3）；需求出现时在文件锁/租约/外部协调间重新决策，属破坏性扩展 |
| 5 | 并发多 Dispatcher 重复取走 processing 消息 | 显式单分发器前提（ADR-6）；多分发器需 `ProcessingSince` + 租约超时，属契约扩展 |
| 6 | 同一 outputPath 被多个 taskID 世系共享 → 分块与最终文件互相覆盖 | 契约「一产物路径一世系」（设计 §5.4.1）；绑定指纹拦不住各自的自洽绑定；Task 世系句柄在结构上绑定单 id，缓冲但不消除该风险 |
| 7 | 绑定指纹只覆盖路径，源内容同路径被换（同尺寸换数据）无法机制化 | 契约（ADR-10）；部分场景由源侧 Align 大小校验兜底；可选 `Identifiable` 身份接口等真实消费方出现再引入（同疑点 #2 纪律） |

## 3. 验收清单（发布前逐项核对）

- [ ] 约束清单（设计 §8，共 30 条）逐条有对应实现或测试锚点
- [ ] 幂等重入探针覆盖导出与导入两条链路；分块导出断言最终文件逐字节等于源数据
- [ ] 四条关键流程（设计 §6）各有端到端测试，含标注的崩溃点
- [ ] 每个哨兵错误有 `errors.Is` 判别测试；filestore 错误同时可判别哨兵与 OS 根因
- [ ] Saga：指纹不一致拒绝恢复、补偿重试/超时、终态三分、Resume 跳过已补偿，均有测试
- [ ] Outbox：processing 重取、终败消息跳过不阻断、`ErrDuplicateID` 幂等 Append、恢复窗口对齐，均有测试
- [ ] 便捷糖（ADR-10）：`Task.Run`/`RunWithOutbox` 与显式路径等价；绑定指纹三态（首 checkpoint 覆盖、缺失即拒、错配拒绝）两侧均有测试；`DispatchUntilIdle` 停止语义（无进展即停、不排空）有测试
- [ ] Collector（ADR-11）：Restore 每实例一次（二次调用不清空在册）、重放 Add 幂等不重复、跨进程还原后增量收集不丢失、Flush 保留其他命名空间且空集不写，均有测试
- [ ] producer 骨架（ADR-12）：全流程、派生失败重放续收（同实例幂等消化 + 全新实例还原）、空源、末批同次 EOF，均有测试
- [ ] 文档断言与代码行为一致（包文档、README、示例注释），无「契约写了机制没跟」的条目
